# 测试数据与错拼变体工具

[返回 PronCFT 首页](../README.md)

本文档说明当前已发布工具的实际行为。命令均在仓库根目录执行；`examples/` 仅含人工示例。论文实验与当前工具的对应关系见[评测与发布范围](evaluation.md)。

独立的英文错拼数据构造工具：把候选词改成指定词表中不存在的拼写，保留调用方提供的音素标签，并同步转写与目标词标签。支持普通转写、带 `<phoneme>/<match>` 标注的文本，以及只改候选词而不改参考转写的对照数据。

仅依赖 Python 标准库，建议 Python 3.8 或以上；离线、CPU、单进程运行，无需安装第三方包。仓库根目录的 Python 文件组成独立工具包，可整体复制使用。

## 文件

| 文件 | 用途 |
|---|---|
| `misspell_rules.py` | 单步规则、词表加载、1～2 步错拼采样 |
| `misspell_io.py` | 通用 JSONL、候选解析、文本替换及安全输出 |
| `build_misspell_cot.py` | 带音素／匹配标注的错拼变体构造 |
| `make_misspell_phonectx.py` | 普通转写错拼及候选词扰动对照 |
| `compute_misspell_recall.py` | 假拼、原拼、双命中、未命中与缺失预测统计 |
| `test_misspell.py` | 仅使用人工数据的标准库单元测试 |
| `examples/` | 人工编写的小词表与输入示例 |

这里只提供文本数据工具，不包含模型、训练框架、语音适配、训练调度、蒸馏实现、音频文件或真实数据集。示例全部人工编写，不携带私有合并词典。

## 规则与真实保证

**“音素不变”指输出沿用输入标签，不代表新拼写按英语自然规则朗读时严格同音。** 规则只做字符串编辑，没有调用 G2P 或音频模型验证新拼写的发音。

### 1. 辅音规则

- `c` 在 `e/i/y` 前可换为 `s`。
- `c→k`、`ck→k`、`ph→f`、`qu→kw`、`x→ks`。
- `g` 在 `e/i/y` 前可换为 `j`；`tch→ch`。

实现中的 `c→k` 是无条件变换，不限于硬音 `c`，也不排除 `ch`。因此某些结果并非自然同音。

### 2. 元音及组合

同组字符串可以相互替换：

| 组标签（仅作规则命名） | 可互换拼写 |
|---|---|
| IY | `ee / ea / ie / i` |
| OW | `oa / ow / o` |
| AW | `ow / ou` |
| UW | `oo / u / ew` |
| EY | `ai / ay / ei` |
| AY | `igh / ie / y / i` |
| ER | `er / ar / or / ur` |

另有单字母 `a/e/i/o/u` 互换。实现不识别实际音素、重音或弱读位置；组名不是音素匹配条件。

### 3. 双写

对辅音集合 `bcdfghjklmnpqrstvwxz`：

- 已有双写辅音可以减一个。
- 任意集合内辅音可以加一次双写。

### 4. 删除与插入

- 词首：`kn→n`、`gn→n`、`wr→r`、`wh→w`、`ps→s`、`pt→t`。
- 词尾：`mb→m`；`le/re/ne/ve` 可删除末尾 `e`。
- 任意位置删除 `gh`；词首 `h` 后为元音时可删除 `h`。
- 对词首 `n/r/w`，分别前缀 `kn/gn`、`wr`、`wh` 到**完整原词**：`name→knname/gnname`、`rain→wrrain`、`word→whword`。

最后一组保留原规则的实际字符串行为，不是将首字母替换为 `kn/wr/wh`。这些候选仍会经过词表与冲突过滤。

### 5. 采样和拒绝条件

- 每次尝试从原词出发，70% 做 1 步、30% 做 2 步。
- 每一步从当前单词的规则结果列表随机选取；保留列表中重复结果，不对规则类别等权采样。
- 最多尝试 10 次，全部失败返回 `None`。
- 结果须不同于原词，不在外部词表中，不与本条样本的原候选、正文词或已生成假拼冲突。
- 结果包含至少一个字母，字符只限 `[A-Z'-]`；改变的词输出大写，普通正文中未改变的词保留原大小写。
- 词表仅作为排除集合。**词表中不存在不等于世界上不存在，也不代表模型从未见过该拼写。** 正式使用需提供覆盖充分且已确认授权的词表。

## 输入与隐私边界

输入为 UTF-8 JSONL，一行一个对象。候选词使用 ASCII 英文字母，可含撇号与连字符；`context_text` 每个候选占一行：

```text
PHONE(F OW N)
TABLE(T EY B AH L)
```

可在第一条候选前放说明行；输出不保留说明行。第一条候选不会被跳过。候选开始之后的非法行会报错，不静默丢弃。重复词保持重复行，但必须具有相同音素标签，所有出现位置共用一个错拼串。括号内标签逐字符保留，不去重音、不重新推断发音。

目标词由 `oov_labels` 指定：

```json
{"word": "PHONE"}
```

生成命令只输出字段白名单：`id`、`text`、`context_text`、`misspell_map`、`context_map`，以及相应模式下的 `oov_labels`／`variant`。原 ID、文件位置和额外元数据不透传；新 ID 由输入顺序生成。标签对象只保留 `word`。`misspell_map` 仅记录正文中出现的词；只存在于候选表的变化记录在 `context_map`，不进入正文召回分母。

**字段白名单不是内容脱敏器。** `text` 和音素标签来自调用方；如果输入正文或标签本身含敏感内容，仍需另行审核。成功输出仅提供数量统计；预期的文件和格式错误给出通用提示，不打印记录正文、词语映射或输入／输出路径。

所有生成命令要求显式输入／输出／词表路径，默认拒绝覆盖已有输出，也拒绝输出与任何输入重合。无网络请求、外部命令或自动下载。输入校验失败会停止；若之前已写出部分记录，输出可能不完整，需检查退出码并换用新输出路径。

## 快速使用

以下命令在仓库根目录执行；只访问人工示例。输出文件必须尚不存在。

### 普通转写：按不同候选词抽样

```bash
python3 make_misspell_phonectx.py --in examples/plain.jsonl --out plain_misspell.jsonl --vocab examples/vocab.txt --prob 0.5 --seed 42
```

每个不同候选按 `--prob` 抽样，同一词所有出现共用映射。生成失败时保留原词。正文只替换原本出现的候选词，其余候选变化不写入正文。输入若提供 `oov_labels`，其词必须出现在正文，输出同步更新 `word`；标签中的其他字段不保留。

### 只扰动目标候选，参考转写不动

```bash
python3 make_misspell_phonectx.py --in examples/plain.jsonl --out context_misspell.jsonl --vocab examples/vocab.txt --targets-only --context-only --seed 42
```

`--targets-only` 必须提供 `oov_labels`，忽略 `--prob`，要求每个目标存在于候选表和正文。任一目标生成失败就丢弃该条记录，其余候选保持原拼写。`--context-only` 保留参考转写及原目标标签，用映射字段记录候选变化。这是通用的上下文扰动对照，不绑定特定数据集分组。

### 带匹配标注的变体

```bash
python3 build_misspell_cot.py --in examples/cot.jsonl --out cot_misspell.jsonl --vocab examples/vocab.txt --n-var-min 3 --n-var-max 4 --other-prob 0.5 --seed 42
```

输入 `text` 的格式为：

```text
<phoneme>DH AH | F OW N | IH Z | R EH D IY</phoneme><match>[None] [PHONE] [None] [None]</match>THE PHONE IS READY.
```

构造规则：

1. 音素段、匹配段和空白分词后的正文词数必须一致。
2. 每个目标必须有匹配命中；命中词、对应正文词和候选音素必须一致，不靠音素相同重新选择候选。
3. 目标及其他已命中的候选均强制错拼，避免匹配标签与正文不一致；剩余候选按 `--other-prob` 抽样。若剩余候选原本出现在正文，其被抽中后也同步改正文，但保留原来的 `[None]`，不补造命中标签。
4. 强制词失败则重试该变体，普通候选失败保留原词。
5. 每个基样本请求 3～4 个变体，候选行重排，同基样本的映射组合去重；每个变体最多重试 3 次，最终产出可能少于请求数量。
6. `<phoneme>` 内容保持原样，`<match>`、正文和目标词标签同步更新；不从缺失标签推断匹配，不支持歧义同音标签。

这份公开整理版取消了特定数据桶、固定样本总量、训练任务标记及多进程入口；调用方自行选择输入数据。两个生成命令均支持 `--limit N` 限制输入条数。种子按 `seed + 输入记录序号（从 1 开始）` 初始化；相同输入顺序、词表、参数和 Python 版本可复现，改变输入顺序会改变结果。

## 外部词表

`--vocab` 必填，支持：

- UTF-8 纯文本：一行一个词，空行及 `#` 开头注释跳过。
- `.jsonl`：每行一个含字符串 `word` 的对象；其余字段不读取。

```json
{"word": "phone"}
```

内部统一小写。空词表或无效词条报错。`examples/vocab.txt` 仅用于演示，覆盖很小，不能据此声称结果都不是自然词。不附带现有大词典，也不自动下载词典；使用者负责外部词表的数据许可。

## 拼写召回评分

预测文件为一行一个 JSON 对象，`id` 对齐**生成后的源文件**，`hypothesis` 为预测文本。不要用生成前的输入 ID 对齐。可将生成文件里的 `id` 与 `text` 作为人工自一致性预测。

```json
{"id": "sample-000001", "hypothesis": "THE FONE IS ON THE TABLE."}
```

上述拼写仅为格式示例，不保证等于某个随机种子的实际产物。

```bash
python3 compute_misspell_recall.py --src plain_misspell.jsonl --hyp predictions.jsonl
```

每个 `ORIG->FAKE` 对按大小写不敏感的完整词统计：

- `fake`：只有假拼出现。
- `original`：只有原拼出现。
- `both`：两者都出现，单独记账，不合并为假拼成功。
- `neither`：有预测记录，但两者均未出现。
- `missing`：源记录没有对应预测，仍进入总分母。

重复 ID 拒绝评分；`id` 和 `uid` 同时存在时必须一致。预测覆盖率的分母是具有非空 `misspell_map` 的源记录数，同时报告不在源文件中的额外预测数量。带 `<phoneme>/<match>` 的完整输出允许外围空白，剥掉标注后只统计最终正文；疑似标注但格式损坏的预测会报错。命中按每条记录的不同映射词计数，不按重复出现次数计数；计分分母是源文件映射总数。

词边界按 ASCII 英文字符、数字、下划线、撇号和连字符判定；撇号和连字符属于词本体，因此 `'PHONE'` 与 `PHONE` 不视为同一个完整词。这里不是通用 Unicode 分词器，中英混合等场景应先用自己的分词规范处理。

假拼召回只能说明模型是否跟随候选拼写，**单项指标不能证明模型使用了某种内部机制**。字形相似、候选复制和其他线索仍可能形成捷径，需要独立对照实验才能作机制判断。
